How TapeScope reads the chain

TapeScope is a read-only analytics terminal. It never asks for a wallet, never signs anything and never sends a transaction. Everything it shows comes from public X Layer mainnet RPC endpoints (rpc.xlayer.tech, xlayerrpc.okx.com, xlayer.drpc.org) using plain eth_call / eth_getCode / eth_getBalance.

Contracts (X Layer mainnet, chain 196)

Addresses are taken from the official open-source TapeKit kernel (TapeOutProtocol/TapeKit, kernel/src/config.js, verified on-chain 2026-09-19) and re-checked live on every load:

  • Processor factory — 0x1f09daefa827f02cbb40967cc91b259763760761 — cpuCount(), cpuAt(i), isCPU(addr)
  • Container opener — 0x536add8f30f03b69f6fbf29d425a816a0dc50106 — accountOf(processor, id), isOpened(processor, id)
  • SiteRegistry — 0xd6efb7adcc9c83dc4924ad56f6a8e4e969b9adb6 — pathCount, pathsRange, fileInfo, read / readRange
  • DomainBinding — 0x68809fd2fb343aa57d0aeb7f33defe477c9666f9 — monthlyFee() (currently 0 OKB), isContainerLive, containerPaidUntil
  • TapeSend hub — 0xe61a9c7213a6aa616c246a2b569e555b417b25ee — same address on every chain (TAP-10)

Snapshot + live verification

Counting every circuit and site needs thousands of calls, so the overview tables start from a timestamped snapshot (data/snapshot.json, built by data/indexer.mjs from live RPC reads only — no mocks, no third-party APIs). Every snapshot number is labelled SNAPSHOT with its generation time and block. Anything labelled LIVE is read from the chain in your browser on load or on demand, and every snapshot row can be re-verified live (processor “Recount”, site “Verify live”, and the Lookup tab, which is live-only).

Honest limitations

  • Sequential token IDs assumed. Circuit counts probe ownerOf(id) with exponential + binary search, which assumes each processor mints token IDs 1, 2, 3… with no gaps. Spot-checked on sample processors at snapshot time; if a processor ever burns a low ID or mints out of order, its count could be off. The Lookup tab always checks a single circuit exactly.
  • No log scans. Public X Layer RPCs cap eth_getLogs at ~100 blocks, so full-history event scans are impractical; sites are found by probing circuits directly instead. A site is therefore only listed if its container was opened and holds files at snapshot time.
  • Custom .tape names. Name liveness is checked at container level (isContainerLive); individual custom names bound to a container are not enumerated.
  • Snapshot staleness. Processors, circuits and sites created after the snapshot timestamp are not in the tables until the snapshot is rebuilt or the live re-read / lookup is used.
